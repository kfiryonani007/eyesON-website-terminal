# ממשק ניהול EYESON — מה בנוי ומה חייב להיבנות

## המערכת עובדת מקצה לקצה

עריכה בפאנל ← שמירה ← קומיט ל-GitHub ← Vercel בונה ← `build.js` מזריק
← האתר מתעדכן. אין מסד נתונים נפרד, וכל שמירה היא קומיט רגיל עם
היסטוריה ואפשרות חזרה בלחיצה.

### ⛔ לפני העלייה לאוויר: חייבים להגדיר 5 משתני סביבה

בלעדיהם ה-API נכשל בכוונה ולא מכניס אף אחד:

| משתנה | מה זה |
|---|---|
| `ADMIN_PASSWORD_HASH` | הפלט של `node scripts/hash-password.js "סיסמה"` |
| `SESSION_SECRET` | מחרוזת אקראית ארוכה (הסקריפט מייצר גם אותה) |
| `GITHUB_TOKEN` | fine-grained token, הרשאת כתיבה **לריפו הזה בלבד** |
| `GITHUB_REPO` | `kfiryonani007/eyesON-website-terminal` |
| `GITHUB_BRANCH` | `main` |

**הסיסמה עצמה לא נשמרת בשום מקום** — רק ה-hash. אין דרך לשחזר אותה,
רק להחליף.

## מה כבר בנוי

| קובץ | תפקיד |
|---|---|
| `content/site.json` | מקור האמת לכל הטקסט באתר |
| `build.js` | מזריק את ה-JSON לתוך ה-HTML |
| `admin/index.html` | מבנה הפאנל + מסך התחברות |
| `admin/admin.css` | עיצוב לפי הרפרנס: סרגל צד + טופס |
| `admin/admin.js` | סכמת השדות, רינדור הטופס, מעקב שינויים, שמירה |

הפאנל מכסה 12 סקשנים: פרטי קשר, סרגל עליון, תפריט, מסך פתיחה, מי אנחנו,
הסיפור שלנו, רצועת מספרים, תהליך העבודה, סקשן הבעיה, EyesOn Screen,
כותרות לגוגל, ופוטר. הוספת שדה = שורה אחת במערך `SCHEMA` ב-`admin.js`.

## שלב הבנייה

```bash
node build.js           # כותב
node build.js --check   # הרצה יבשה, מדווח מה היה משתנה
```

אפס תלויות, Node מובנה בלבד.

**הגישה: הזרקה ממוקדת, לא תבניות.** ה-HTML נשאר HTML תקין שאפשר לערוך
ביד. אלמנט שניתן לעריכה מסומן בתכונה:

```html
<p data-cms="footer.tagline">הטקסט הנוכחי</p>
<a data-cms-attr="href:contact.whatsappUrl" href="https://wa.me/...">
```

הסקריפט נוגע רק במסומנים. מפתח חסר ב-JSON פירושו שה-HTML נשאר כמו שהוא,
כך שבנייה לא מוחקת תוכן בטעות. כל ערך עובר escaping לפני ההזרקה, אז טקסט
שנכתב בפאנל לא יכול להזריק HTML לאתר.

`tel:`, `wa.me` ו-`mailto:` **נגזרים** מהמספר ומהמייל בזמן הבנייה, כך
שהתצוגה והקישור לא יכולים להיפרד.

**מצב נוכחי: 134 נקודות מסומנות ב-8 עמודים.**

מסומן ועובד:

- **כל פרטי הקשר בכל האתר** — פוטר, עמודים משפטיים, כפתור הוואטסאפ הצף,
  כפתור הוואטסאפ בעמוד השירות, ויעד טופס יצירת הקשר.
- **כל כותרות הדפדפן ותיאורי גוגל** בשמונת העמודים.
- סלוגן ההדר, קישורי הרשתות, קרדיט הפוטר.
- כותרת ההירו וכפתוריו, סקשן "מה מייחד אותנו", דרישות EyesOn Screen.

`js/main.js` כבר לא מכיל את כתובת המייל בקוד. הטופס מקבל אותה בתכונה
`data-contact-email` שהבנייה כותבת, וה-JS קורא משם.

### עוד לא מסומן

תת-הכותרת בהירו, הסרגל העליון, כרטיסי "מי אנחנו", שלבי התהליך, הגרף,
ועמודות הפוטר. כולם טקסט שיווקי בלבד — **אין בהם פרטי קשר**, ולכן עריכה
בפאנל כבר לא יכולה ליצור אתר עם טלפון או מייל סותרים.

`build.js` תומך בהדגשה מבוקרת (`**טקסט**` הופך ל-`<strong>`), כך שאפשר
לסמן גם את הפסקאות שיש בהן הדגשה פנימית כשנגיע אליהן.

## שכבת השרת — בנויה

```
GET  /api/session   ->  200 { "authenticated": true|false }
POST /api/login     ->  200 { "ok": true }  |  401
                        body: { "password": "..." }
GET  /api/content   ->  200 <site.json>          (דורש סשן)
POST /api/content   ->  200 { "ok": true }       (דורש סשן)
                        body: <site.json>
```

מה שמומש בפועל:

- סיסמה מאוחסנת כ-hash מסוג **scrypt** במשתנה סביבה. ההשוואה
  ב-`timingSafeEqual`, לא ב-`===`.
- סשן ב-cookie חתום ב-HMAC-SHA256, עם `HttpOnly`, `Secure`,
  `SameSite=Strict` ותפוגה של 8 שעות. לא `localStorage`.
- `/api/content` מאמת את הסשן **בעצמו** בכל בקשה. הסתרת הכפתור בלקוח
  לא נחשבת הגנה.
- בדיקת Origin נוספת על כל POST.
- ולידציה של ה-JSON הנכנס ומגבלת גודל (512KB).
- הקומיט נשלח עם ה-sha הנוכחי, כך ששני עורכים לא יכולים לדרוס זה את זה.
- `build.js` רץ אוטומטית ב-Vercel דרך `buildCommand` ב-`vercel.json`.

**מגבלה שצריך להכיר:** הגבלת הקצב על ההתחברות (8 ניסיונות ל-15 דקות)
נשמרת בזיכרון של מופע ה-serverless. היא מאטה תוקף אבל לא חוסמת אותו
לחלוטין, כי Vercel יכול להרים מופעים נוספים. לחסימה מלאה צריך להעביר
את המונה ל-Vercel KV. הסיסמה החזקה היא ההגנה העיקרית.

## בדיקות שבוצעו

- הפאנל נפתח מול השרת המקומי: 12 הסקשנים נטענים, השדות מתמלאים
  מ-`site.json`, מעבר בין סקשנים עובד, כפתור השמירה מנוטרל בהיעדר API.
- `node build.js --check` על המצב הנוכחי: 134 נקודות, אפס שינויים,
  כלומר ה-JSON מראה נאמנה את ה-HTML והבנייה אידמפוטנטית.
- מחזור מלא על פרטי הקשר: הוחלפו טלפון, וואטסאפ ומייל ב-JSON, הורץ
  `build.js`, ואומת ש-62 ערכים התעדכנו. **חיפוש אחרי הערכים הישנים
  בכל קבצי ה-HTML וה-JS החזיר אפס** — כלומר לא נשאר פרט קשר מיושן
  בשום מקום. לאחר מכן שוחזר ה-JSON והאתר חזר בדיוק למצבו.
- ה-escaping נבדק ביחידה: `<script>alert(1)</script>` יוצא מנוטרל,
  ו-`**טקסט**` הופך ל-`<strong>` כמצופה.
- כל 8 העמודים עוברים ניתוח HTML ללא שגיאות, אפס escaping כפול,
  ותיקוני ה-RTL (bdi, מרכאות) שרדו את ההזרקה.
- לא נבדק מול שרת אמיתי — הוא לא קיים עדיין.
